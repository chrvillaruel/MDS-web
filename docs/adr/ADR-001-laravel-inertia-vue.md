# ADR-001: Laravel 13 + Inertia + Vue 3 over Livewire and decoupled SPA

- **Status:** Accepted
- **Date:** 2026-05-06
- **Deciders:** @christian, @ed
- **Linear:** SOF-286

## Context

MDS is a server-heavy compliance product: invoice issuance, BIR-mandated PDF
generation, bulk imports from Shopee/Lazada/TikTok, X/Z-Reading reports, audit
journal, and accreditation paperwork. The UI surface is small and form-heavy
(seller wizard, invoice editor, bulk-upload review, buyer self-service link).
Two engineers ship six milestones in six months under a hard regulatory
deadline (BIR mandate Dec 2026).

We need a stack that:

1. Lets two engineers move fast on full-stack features without an API surface
   to maintain.
2. Keeps Eloquent + Laravel ecosystem (Cashier, Horizon, Pulse, Pennant,
   Scout, Fortify, Telescope) as the source of truth for state — these all
   assume server-rendered or Inertia-style flows.
3. Produces a JS bundle small enough that Filipino sellers on slow mobile data
   can use it.
4. Doesn't fight TypeScript / shadcn-style component primitives, since we
   want strict types on every form payload.

## Decision

Inertia + Vue 3 + TypeScript on top of Laravel 13.

Routes return `Inertia::render('Page', $props)` instead of JSON. Vue 3 with
`<script setup lang="ts">` and `defineProps<...>()` types every page payload.
shadcn-vue + Tailwind v4 give us copy-in primitives — no opinionated
component library to fight when a BIR field shape forces a custom layout.

## Alternatives considered

- **Livewire 4** — fewest moving parts, but compliance forms with conditional
  visibility, multi-step wizards, and the buyer-link flow benefit from a real
  client-side reactivity model and TS-typed props. Livewire's wire-level
  diffing also makes the bulk-upload review screen (1k+ rows) hard.
- **Decoupled Vue/React SPA + Laravel API** — duplicates auth, validation,
  and CSRF concerns; doubles the surface area two engineers maintain;
  Cashier/Fortify/Pennant lose half their value when not driving views
  directly.
- **Blade + Alpine** — fine for marketing, not for the seller dashboard.
  Rejected for the product surface.

## Consequences

- Easier: one codebase, one router, one auth stack; Cashier/Fortify drop in;
  page-level type safety via shared DTOs serialized by Laravel.
- Harder: SSR is opt-in (we ship the `ssr.ts` entry but don't run SSR until a
  perf budget forces it); we own the Vite + Inertia + TS toolchain rather
  than getting it generated by a starter kit.
- Reversibility: page-level. Any single Inertia page can be replaced by an
  API + standalone SPA route without rewriting the rest. We're not betting
  the whole product on Inertia — only the dashboard surface.
